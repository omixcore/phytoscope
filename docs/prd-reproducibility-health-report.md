# PhytoScope 增量 PRD：可执行记录导出 · 一致性体检 · 区间候选基因报告

## 1. 项目信息

- **Language**：中文（与用户需求一致）
- **Programming Language**：Java 21（Spring Boot + JavaFX 桌面应用，沿用现有技术栈，不引入新框架）
- **Project Name**：phytoscope
- **PRD 类型**：简单增量 PRD（默认档，不含竞品分析）
- **原始需求复述**：在现有 PhytoScope 桌面应用基础上，新增三块能力——(1) 从项目状态反向生成可重跑的 CLI 复现记录；(2) 对导入的 GFF3/GTF 注释做分级一致性体检；(3) 对区间查询输出可追溯、不排名的候选基因证据报告。三者依赖两个前置修复：修正 `applicationVersion` 硬编码、补全 `Gff3Parser` 的原始数据捕获。

## 2. 产品定义

### 2.1 产品目标（本次增量价值主张）

本次增量把 PhytoScope 从"能看"推进到"能验、能查、能交付"，呼应产品定位 *"portable local queries of plant genome data"* 的论文级闭环：**用户自带数据 → 导入即体检 → 位点/区间查询 → 导出一键可重跑结果**。

1. **可复现（Reproducibility）**：把"已由 CLI 覆盖的两条路径（批量渲染、比较）"从项目状态反向还原为等价命令行 + 输入清单 + 校验步骤，使论文图形与表格可在干净环境被第三方独立复现，而非仅凭作者描述。
2. **数据可信（Health）**：导入注释时输出分级报告，明确区分"错误 / 警告 / 未检查"，在分析前暴露坐标越界、缺失 Parent、非法 phase、CDS 长度异常等数据质量问题，避免"垃圾进垃圾出"。
3. **可追溯（Traceability）**：区间查询产出逐基因证据卡，只汇总不排名，对负链、多转录本、缺失表达逐一显式标注，让候选基因结论可被独立核对而非黑盒打分。

> 明确边界：本次**不**做"复现一切 GUI 操作"（区间/启动子/CDS 提取、Sequence QC、Sample groups、Homology、Domains、模糊搜索、交互缩放平移均无 CLI 等价物），**不**输出"最可能致因基因"排名（无经验证的评分模型）。这两点是正确性定义的一部分，不是能力缺口。

### 2.2 用户故事

**模块① 可执行记录导出**
- 作为研究者，我希望从 `.phytoscope` 项目一键导出可重跑脚本（reproduce.sh/.bat + inputs/ + 校验文件），以便同行在干净环境复现与我一致的序列、数据表和关键图形。
- 作为审稿人/复现者，我希望复现目录中的 `UNCOVERED.md` 明确列出"哪些 GUI 操作没有 CLI 等价物"，以便知道我核对到的是哪一部分结论。

**模块② 一致性体检**
- 作为数据管理员/导入者，我希望导入 GFF3/GTF 时立即看到分级健康报告（错误/警告/未检查），以便在进入分析前定位 Parent 缺失、坐标越界、非法 phase、CDS 非 3 倍数等问题。
- 作为注释维护者，我希望 CDS 非 3 倍数不一律被判错，而是结合是否缺失 ATG/终止密码子分类（不完整 CDS vs 注释约定 vs 真实异常），以便得到可操作而非误报的诊断。

**模块③ 区间候选基因报告**
- 作为遗传学家，我希望对某区间/位点查询得到候选基因证据卡，清楚看到每个基因与区间的重叠关系（完整/部分）、结构、表达（缺失标"无表达"而非猜值）与来源，以便自行判断而非被动接受"最可能基因"。
- 作为下游分析者，我希望每条证据卡都能追溯到原始注释行/表达矩阵条目，以便复核负链、多转录本、缺失表达等易错点。

### 2.3 关键约束（已核对事实，PRD 的硬性前提）

- `ProjectStore` 保存的是"当前快照"（`ViewState`/`ResearchState`/`Source`），不是操作历史；`Source` 通过 entry/origin/sha256 将注释源字节与表达矩阵嵌入 ZIP 并做 SHA-256 校验。
- `Manifest.applicationVersion` 目前硬编码为字符串 `"0.2.0"`（第 84 行），未从构建元数据读取——发布 v0.2.1 后该字段将是错误值，必须修复。
- CLI 仅两条独立路径（`PhytoScopeLauncher` 分发）：`BatchRenderer` 与 `ComparisonRunner`。其余 GUI 研究操作无 CLI 等价物。
- `Gff3Parser` 解析时丢弃关键原始信息：`RawFeature.fromColumns` 未读第 5 列 score、第 7 列 phase；`skippedRows` 只记计数不记"哪一行、为什么"；孤儿 Parent 在 `resolveTranscripts` 中被 `.filter(nonNull)` 静默丢弃。

## 3. 技术规范

### 3.1 需求池（按优先级）

#### P0.1 修复 `applicationVersion` 硬编码
- **Must**：`Manifest.applicationVersion` 改为从构建元数据读取（如 Maven `project.version` 经资源过滤/`build-info` 注入），发布 v0.2.1 时该字段应自动为 `"0.2.1"`，无需手工改代码。
- **Must**：保留回退策略——若构建元数据不可得，回退到既有默认值，避免空值破坏项目可移植性。
- **Should**：补充单测验证"版本号与 pom 版本一致"。

#### P0.2 `Gff3Parser` 补数据捕获（体检模块的数据来源）
- **Must**：`RawFeature` 捕获第 5 列 `score` 与第 7 列 `phase` 的**原始字符串**（不强制转数值，GFF3 中常见 `"."` 表示未知）。
- **Must**：`skippedRows` 从 `int` 计数升级为结构化记录（行号 + 原始行内容 + 跳过原因枚举）。
- **Must**：孤儿 Parent（指向不存在 ID）不再被静默丢弃，而是保留为结构化"孤儿证据"（Parent ID、所在行、关联 feature 行号），供体检模块报告为错误。
- **Must**：这些新增字段对既有解析行为**向后兼容**（不改变正常 GFF3/GTF 的解析结果与下游数据结构，仅新增诊断信息）。
- **Should**：结构化跳过诊断在内存占用上做上限保护（异常文件可能有海量跳过行）。

#### 模块① 可执行记录导出（复现记录）— P0
- **Must**：正确定义 = 仅对**已被 CLI 覆盖的两条路径**（`BatchRenderer` 批量渲染、`ComparisonRunner` 比较）从 `ProjectStore` 当前快照反向生成等价命令；**不**尝试复现无 CLI 等价物的 GUI 操作。
- **Must**：产出标准复现目录，包含：
  - `reproduce.sh` / `reproduce.bat`：**真实 CLI 命令**，参数逐项映射（如 `ViewState.sequence → --gff3`、`comparisonGenes → --loci`、`alignment/scale/compress-introns → --alignment/--scale/--compress-introns` 等），禁止写示意性/占位命令。
  - `inputs/`：从 ZIP 解包真实注释源字节与表达矩阵（复用 `Source.sha256` 校验解包完整性）。
  - `SHA256SUMS.txt`：对 inputs 内每份文件列出校验和。
  - `VERSION.txt`：记录生成该记录时的应用版本（依赖 P0.1 的修复）。
  - `UNCOVERED.md`：明确列出无 CLI 等价物的 GUI 操作清单（区间/启动子/CDS 提取、Sequence QC、Sample groups、Homology、Domains、模糊搜索、交互缩放平移）。
- **Must**：`--no-expression` 若当前实现为空操作，导出命令须按"实际行为"映射（不虚构"禁用表达"语义），并在 `UNCOVERED.md` 或脚注中如实说明。
- **Should**：导出时校验当前项目状态能否被两条 CLI 路径覆盖；若不能（如研究态字段涉及未覆盖模块），显式降级并在报告中标注"该快照包含不可复现组件"。

#### 模块② 一致性体检（AnnotationHealthService）— P0（先于③交付）
- **Must**：新增 `AnnotationHealthService`，输入为带原始诊断的解析结果（依赖 P0.2），输出分级报告，三级：
  - **错误（Error）**：Parent 缺失（孤儿 Parent 指向不存在 ID）、坐标越界（start>end、越出序列长度等）。
  - **警告（Warning）**：CDS 长度非 3 倍数（需分类，见下）、非法 phase 值（非 `0/1/2/`.`）、表达矩阵中的 ID 与注释 ID 不匹配。
  - **未检查（Not checked）**：如"组装版本匹配"——坐标合法 ≠ 组装匹配，PhytoScope 无组装版本校验能力，必须显式标注为"未检查"而非默认通过。
- **Must**：CDS 非 3 倍数不一律判错，按优先级分类：
  1. 缺失起始密码子（ATG）或终止密码子 → 判定为"不完整 CDS"（警告，提示可能为边界转录本）。
  2. 符合注释约定（如 `partial=true`、已知非 3 倍数约定）→ 判定为"注释约定"（提示而非警告）。
  3. 其余 → "真实异常"（警告，提示需人工复核）。
- **Must**：报告可定位到行级证据（行号 + 原始行 + 原因），与 P0.2 的结构化诊断一一对应。
- **Should**：提供 CLI/报告两种输出形式（人类可读 + 机器可读如 JSON/TSV），便于批量体检。

#### 模块③ 区间候选基因报告（CandidateGeneReportService + 证据卡）— P0
- **Must**：新增 `CandidateGeneReportService` + 证据卡渲染器；只汇总不排名，**不输出**"最可能致因基因"或任何未经验证的评分。
- **Must**：每基因证据卡至少包含：
  - 重叠关系：完整重叠 / 部分重叠（并给出重叠区间坐标）。
  - 结构：外显子/CDS/UTR/转录本结构摘要。
  - 表达：有值则展示；表达矩阵缺失该基因 → 显式标注"无表达"，**不猜值、不补零**。
  - 来源：可追溯到原始注释行号 + 表达矩阵条目（ID/样本）。
- **Must**：以下易错点逐一显式标注：**负链**（坐标方向）、**多转录本**（每个转录本各自重叠关系）、**缺失表达**（区分"无表达记录"与"表达值为 0"）。
- **Should**：证据卡支持导出（如 Markdown/HTML/CSV），便于附在报告或回复审稿意见。

### 3.2 UI 设计草案（基础布局）

- **体检**：导入完成后或独立"体检"入口触发；以"错误 / 警告 / 未检查"三段式列表展示，每项可展开到行级证据。
- **区间报告**：在现有区间/位点查询结果区，以基因卡片列表呈现；每张卡片含重叠关系徽标（完整/部分）、结构摘要、表达行（或"无表达"灰显）、来源链接。
- **复现导出**：项目菜单或工具栏新增"导出复现记录"动作；导出成功后展示复现目录结构概览与 `UNCOVERED.md` 摘要。

### 3.3 关键验收标准（验收时必须覆盖用户明确的三条）

1. **复现 = 新目录跑脚本结果一致**：在**全新的干净目录**（或干净机器）中，仅凭 `reproduce.sh`/`.bat` + `inputs/` + 校验文件执行，得到与源项目**一致的序列、数据表、关键图形**（关键图形以像素/结构级可比为准，允许时间戳等元数据差异；`SHA256SUMS.txt` 校验 inputs 无损）。
2. **体检 = 预设异常数据能检出且分级正确**：用构造的预设异常 GFF3/GTF（含孤儿 Parent、坐标越界、非法 phase、CDS 非 3 倍数、表达 ID 不匹配、组装版本场景）跑体检，须能**检出全部异常**，并**正确落入错误/警告/未检查三级**（尤其：CDS 非 3 倍数按"不完整/约定/异常"分类；组装版本匹配归入"未检查"而非默认通过）。
3. **区间报告 = 独立核对且可追溯**：用已知答案的区间测试集（覆盖**边界重叠、负链、多转录本、缺失表达**四类）跑报告，第三方能**独立核对**每张证据卡的重叠关系、结构、表达、来源；每条证据卡须**可追溯**到原始注释行号与表达矩阵条目；缺失表达须标注"无表达"而非补零或猜值。

### 3.4 待确认问题

1. **phase 与 score 的"未知值"语义**：GFF3 中 `phase` 常为 `.`（未知）而非 `0/1/2`。体检是否将 `.` 归为"未检查/合法未知"，而仅将**其他非法值**（如 `3`、`-1`、非数字）判为警告？需要确认判定标准。
2. **CDS 非 3 倍数的"注释约定"如何界定**：目前依赖 `partial=true` 或特定约定；若数据源没有 `partial` 标记，是否需要额外的启发式（如"位于 transcript 首/末端的 CDS 允许非 3 倍数"）？请确认默认策略。
3. **"表达值为 0" 与"无表达记录"的展示区分**：验收要求缺失表达标"无表达"，但表达矩阵中存在 `0` 值时应显示为"0"还是"无表达"？建议区分，请确认。
4. **复现目录的默认输出位置与命名**：默认输出到项目目录（如 `<project>/reproduce/<timestamp>/`）还是用户自选？是否需要覆盖保护（已有同名目录时的行为）？
5. **关键图形"一致"的判定粒度**：像素级一致、结构级一致（渲染参数相同但允许字体/抗锯齿差异）、还是仅"图形内容等价"？这决定复现验收的可自动化程度，请确认。
